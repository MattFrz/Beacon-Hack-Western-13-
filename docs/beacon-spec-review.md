### Finding

**P0 — LIVE < 300 ms is incompatible with capture-time aging plus the spec’s own detector proxy. Spoken metres and full-rate REACH ticks are often illegal at birth.**
- **Section:** 6 (mode table), 7 Range 2, 10 HOLD, 4 budget table.
- **Evidence:** Mode table: age `< 300 ms` → LIVE “full REACH or WALK speech”; `300 ms`–`1.5 s` → HOLD “no new metres spoken”; HOLD REACH is “darker/slower tick.” Range 2: “Repeat every ~3 s from a **fresh** measurement. If the box is gone, do not keep saying four metres.” Section 6 requires the original capture timestamp. Section 4’s own YOLOE proxy is “Linux proxy ~200–333 ms at 320”; Henomaly YOLO11n is 168 ms on this class of board. If `last_seen_ns` is capture time, age at publish ≈ inference latency. At 300–333 ms the target is HOLD **before guided reads it**, so WALK must not speak metres and REACH never enters full LIVE. Even 168 ms leaves only a short LIVE sliver per cycle. QNX YOLOE p95 is **unknown**; this P0 does not invent it. It is already true on the numbers the spec cites.
- **Smallest fix:** Define LIVE as “the latest completed percept output still contains this name,” stamp `last_seen_ns` as capture time for honesty but **do not** use a 300 ms wall-clock gate that is tighter than p95(yolo)+p95(depth). Example: LIVE while `now - last_seen_ns` < max(1.0 s, 2× measured p95). HOLD = no box, last_seen < 1.5 s. Speak metres only from that completed output, labeled approximate.

**P0 — Geometry is not closed. Guided cannot unproject a fingertip from the published shm contract, and crop→full-frame→depth maps are named but not written.**
- **Section:** 5 guided steps 2–3, 5 percept steps 4–5, 6 WorldState, 7 unprojection, 8 VO step 3, 10 REACH `d = |hand.xyz_cam − target.xyz_cam|`.
- **Evidence:**
  1. Guided: “Unproject that pixel through the latest depth sample.” WorldState has pose, hand, target, objects[32], crumbs[512], health, intent. **No depth map, no Z sample, no `/beacon_depth`.** Frame ring is RGB/NV12 pixels only. Depth lives in percept’s heap. REACH as specified cannot be implemented from the two shm regions.
  2. Section 7: “Every box and landmark is mapped to that full-frame pixel grid before depth is sampled.” Percept step 4: “YOLO 320 and depth ~210 are letterboxed crops… Sampling a 320-px box centre on a 210-px depth map is fiction.” That warning is correct. There is still no inverse: no scale/pad/axis, no `(u320,v320)→(u_full,v_full)→(u_depth,v_depth)`, no mask for letterbox padding. Intrinsics are “at the resolution `camd` actually publishes,” but that `W×H` is not locked (section 17 only locks unit/frametype).
  3. Guided MediaPipe is “on a downscaled crop.” Landmark 8 is in crop space. No crop inverse onto the calibrated grid. Without it, hand unprojection is fiction in the same way as 320-on-210.
  4. Range 1 claims “the **same** depth map” and `d = |p_hand_cam − p_target_cam|`. Hands run at 30–60 Hz in guided; depth ~8 Hz and boxes ~3–6 Hz in percept. Those xyz_cam vectors are not the same camera frame. No `frame_id` check before subtracting. Chest rotation makes camera-frame subtraction wrong; Range 1 forbids requiring `pose.valid`.
  5. Section 8 VO: “3D in `K` from that pixel’s depth” with ORB at ~320×240 and depth at ~210. Same missing map. `T_world_from_F = T_world_from_K · inverse(T_F_from_K)` is the right multiply **if** solvePnP is `T_F_from_K`; the 4×4 vs 3-vector homogeneous multiply is left implicit.
- **Smallest fix:** (a) Publish a seq-protected depth slot (`/beacon_depth`: `W_d, H_d`, metres, letterbox affine, source `frame_id`). (b) Write both affines once: YOLO 320 and depth ~210 are independent letterboxes of the published frame; unproject only with full-frame `(fx,fy,cx,cy)` after inverse map; do not sample padded pixels. (c) Same inverse for MediaPipe crop. (d) REACH subtract only if `hand.frame_id == target.frame_id`, else hold last `d` or, if `pose.valid`, `target` in current cam from `xyz_world`. (e) Lock `camd` published `W×H` before calibration. Do not invent a 16 ms or depth-ms number here; this is a missing contract.

**P1 — WorldState has three writers and one seq. `target` has two specified authors. Restart + never-delete objects can retarget a ghost.**
- **Section:** 5 process contracts, 6 shm, 9 step 4, 15 freeze-percept test.
- **Evidence:** voiced writes `intent`. percept writes pose, objects, target (step 8: “set `target` to the best match”), crumbs, health percept fields. guided writes `hand`, computes `target.mode` (section 6: “computed in `guided` from age, not wished by `percept`”), health guided. Section 9 step 4 contradicts 5.8: “`guided` sets `target` to the matching object.” One seq “odd while writing, even when stable” is a single-writer protocol. Three writers lose updates or publish a torn `WorldState`. Percept memcpy of `target` clobbers `mode`. `crumbs[512]` has no head/count, so RETURN cannot append. Restart “does not zero `objects[]`” plus “Do not delete a row when it leaves the camera” plus “nearest if two”: after `slay percept` and a moved cup, stale `xyz_cam` from a previous pose epoch still competes. Section 15 wants “first resumed cue matches a **new** placement.” Ghost nearest can fail that. Mid-write crash can leave seq odd; restart does not mention repairing it.
- **Smallest fix:** Split by writer, each with its own seq (or a mutex + one writer). percept owns pose, objects, target geometry, crumbs (+ `crumb_i`/`crumb_n`). voiced owns intent. guided owns `hand` and **does not store mode** (mode = f(now, last_seen_ns) locally). Only percept sets `target` from FIND/GO, or only guided does — pick one; delete the other sentence. On percept start: if seq odd, skip torn blob; bump a `pose_epoch`; do not use object xyz from another epoch for “nearest.” Evict or ignore rows older than the LOST gate for targeting; keep them for the session list.

**P1 — 16 ms guided deadline vs MediaPipe + depth reuse is a hope, not a budget. 5–10 ms is unsourced. Uncompressed full-frame convert on core 0 can miss the deadline without any model.**
- **Section:** 4 table, 5 guided loop and core 0 pin, 13 step 1 vs step 3.
- **Evidence:** Hands: “5–10 ms (must stay inside the 16 ms deadline).” No QNX measurement, no Linux citation. Treat as **unknown**. Nov 20 plan A1/B7 put MediaPipe on cores 1–3 and forbade model calls on the timing thread. This spec moved palm+landmark **into** guided on core 0. Depth is ~8 Hz (120 ms Linux proxy, **unknown** on QNX), so `d` cannot be a fresh 60 Hz 3D measurement; Nov 20 C2 said “A 60 Hz loop does not create 60 fresh hand measurements per second” and this spec dropped that sentence. Guided still “Write USB audio” inside the 16 ms loop; USB can block. camd on core 0 writes uncompressed Camera Module 3 frames (section 4: “Frames are uncompressed”). Convert-once is “in the consumer, not in `camd`” — guided is a consumer. Full-frame NV12→RGB at tabletop res is enough to blow 16 ms; the spec does not forbid it. MediaPipe/ORT thread pools are not pinned; they can leak onto cores 1–3 or stay on core 0. Supervisor kills guided after two missed 50 ms beats (~100 ms). If landmark is slow, the prize path suicides mid-REACH. QNX MediaPipe Hands from a chest-down tabletop view (not the usual facing-camera workshop pose) is **unknown**.
- **Smallest fix:** Keep guided as a 60 Hz **synthesizer**: piezo/USB-off-thread, no blocking writes. Run MediaPipe at ~10–15 Hz (depth-limited) in a worker, pin its threads, feed `hand` through a tiny seq slot. Crop/scale from mmap **without** converting the full published frame. Restore the Nov 20 sentence that 60 Hz ≠ 60 unique 3D samples. Build step 1 stays fake-target busy-loop; step 3 is a **hard gate**: if landmark+unproject+tick misses 16 ms p95 under the cores 1–3 hog, move hands off core 0 or drop REACH ticks (section 14 already says broken hands → walk speech only). Do not treat 5–10 ms as a QNX fact.

**P1 — YOLOE + depth + VO + whisper + llama on one SoC is not the cadence table. Three v1 journeys in one 30 s run is not honest even if RETURN is droppable.**
- **Section:** 4 table, 5 percept as one process, 1 journey table, 3 Sunday journeys, 12 script, 13 order, model brief proxies.
- **Evidence:** Table lists depth ~8 Hz (~120 ms Linux) and YOLOE ~3–6 Hz (~200–333 ms Linux / 168 ms YOLO11n QNX) as if independent. percept is one process, steps 2 then 3 sequential as written. Sequential cycle ≈ 120 + 200–333 ms plus unproject plus ORB+PnP (**VO ms unknown**) → about 2–3 Hz combined, not 8 Hz and 6 Hz. Parallel threads inside percept are not specified. YOLOE-26n in the research brief is the **seg** checkpoint with mask/text-projection branches; the spec never says detect-vs-seg export, so box-only may still pay seg cost. whisper ~0.7 s and llama ~1–2 s are on-command on cores 1–3 at prio 18 during FIND, when YOLO must be live; llama 1–2 s is a **Linux** 0.5B GGUF proxy from the model brief, **unknown** on QNX under load. Thermal on core 0 is warned (“Thermal throttle on core 0 kills the guidance deadline”) with no measured steady state. Section 1 lists three equal journeys. Section 3 puts all three in v1. Section 12 step 2 is in the required 30 s path; only step 3 is optional. Section 13 correctly says (1)–(5) is already the demo. Those four sections do not agree on what Sunday must show. QNX ORT loading the YOLOE graph is **unknown** (model brief open question).
- **Smallest fix:** Rewrite the budget as one percept pipeline: sequential default, optional 2-thread YOLO∥depth, **measured** p50/p95 on the loaner with guided running. Export detect-only if Ultralytics allows. Do not load llama.cpp unless the table misses a judged phrase. Change section 1/3 to: v1 demo = FIND-and-reach + LOST; ask-the-room = in-view only until step 6 is green; RETURN = not in the 30 s script until VO p95 exists. That matches 12–13 and the product lock “RETURN drops if VO is unstable.”

**P1 — WALK/REACH handoff at 0.6 m is underspecified for the states the demo will hit.**
- **Section:** 10 REACH/WALK, 7 Range 1, 16 mount, 14 hands-broken row.
- **Evidence:** REACH requires “hand in frame **and** `|hand − target|` ≲ 0.6 m.” No-hand at 0.4 m (cane down, MediaPipe miss, chest angle) stays WALK speech with no ticks — demo script step 1 dies. Enter/exit is the same 0.6 m with no hysteresis; EMA is on tick interval, not on the law switch → speech/ticks chatter. “Mixing them is a product bug” but there is no “cancel WALK clip on REACH enter.” Two hands: “the hand point” is singular (landmark 8). HOLD continues ticks on last `xyz_cam` for up to 1.5 s after the box/camera dies — phantom REACH if they turn. VO down + object off-camera is refused for Range 3, but REACH can still fire on stale `xyz_cam` if a hand is close to that stale point. Product lock “ticks only when a hand is reaching” makes a hand miss a demo fail, not a fallback.
- **Smallest fix:** Enter REACH at 0.50 m, exit at 0.70 m, N frames. Pick the hand closer to target. Duck WALK audio on enter. REACH only if `target.mode` is LIVE (after the LIVE fix) and `hand.conf` above a threshold. If no hand and `|p_cam|` ≲ 0.6 m: keep WALK, faster repeats, **no ticks** (honor the lock) and treat MediaPipe miss as a demo blocking test on the chest mount (section 16), not as a surprise Sunday.

**P1 — “Refill water” does not resolve to a stored bottle. Table vs llama vs baked list is not an algorithm.**

- **Evidence:** Table row: spoken `refill, water, drink, fountain, sink` → candidates `fountain, dispenser, sink, bottle`. Worked example: “Where can I refill water” → `GO, fountain` “(or `bottle` / `sink` / `dispenser` if that is what was stored).” voiced “Write `intent` only” and must not write `objects[]`; nothing says it may **read** `objects[]` and pick the name that exists. Do not pick a different class.” Walk past a bottle stored as `bottle`, table emits `fountain` → false miss. llama never sees this phrase: table hits first. llama is also not given the session name list. FIND vs GO is not in the table; laws do not distinguish them (section 5.8 treats both as set-target). voiced may “play ‘I did not catch that’” (section 5) while guided owns USB audio (two audio writers). Model brief: remap quality for this phrase is **untested**.
- **Smallest fix:** Table returns a **candidate set** and a job. voiced (or guided) reads `objects[].name` and binds the first stored hit; else “I have not seen that.” Put seen names in the llama prompt only if the table misses. For the 30 s script, lock `water|refill → bottle` (or whatever YOLOE actually labels at the venue). One audio owner: voiced writes `intent.kind = NACK`, guided plays the clip.
